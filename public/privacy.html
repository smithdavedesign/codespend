Privacy policy

Last updated 12 October 2026. Questions go to the project's GitHub issues. Issues are public, so never post a key or personal data there. For data on a CodeSpend server that someone else runs for you, including deletion requests, write to its operator: .

In short

  • The website collects nothing about you beyond the three anonymous events below. It sets no cookies.
  • The CodeSpend app runs on your own machine or server. What it stores stays there, with keys encrypted.

The website and its three events

The website sets no cookies and has no ad trackers, third-party analytics or accounts. To count real use, the official production site sends three events to RepoHQ (repohq.vercel.app), the project owner's own dashboard:

  • visit: once per browser session, when you open a page;
  • activate: once per browser, the first time Sync now succeeds in a CodeSpend dashboard served by the official production deployment;
  • checkout: when you click Get Pro.

Each event contains only the product name ("codespend") and the event name. If you followed a link from another website, it also contains that site's address (the referrer). It never contains the address of the page you are on, and it carries no identifier or cookie. The event doesn't include your IP address, but RepoHQ's server sees it while handling the request, as with any web request.

So that each event is sent only once, the page notes in your browser's session or local storage that it was sent. That note never leaves your browser. Nothing is sent from automated browsers, preview deployments, or CodeSpend servers you run yourself.

What the CodeSpend app stores

  • Vendor API keys and tokens you connect (Anthropic, OpenAI, GitHub, Cursor). They are encrypted at rest with AES-256-GCM, using a key kept apart from the data file. They are used only to read your usage and cost reports, and they are never sent back to your browser or shown again.
  • Slack incoming-webhook URLs, encrypted the same way and never shown again.
  • Alert email addresses, project names and monthly budgets that you enter.
  • Daily cost per tool and project, as reported by each vendor's API, plus the time and short error message of the last sync. Error messages never contain your key.
  • Branch reports sent by the codespend-branches command: date, git branch name, token count, estimated cost and commit count. The command reads Claude Code's logs on your own machine and sends only these totals. It never sends prompts, code, file contents, file paths, names or emails.

All of this lives on the CodeSpend server you run, or that someone runs for you. None of it is sent to the CodeSpend website or to RepoHQ. The app itself sets no cookies.

Who else sees data

  • The AI vendors: each connected key is sent only to its own vendor's API, to fetch your usage.
  • Email: if email delivery is configured (SendGrid), alert emails pass through it: recipient, subject and the spend summary.
  • Slack: alerts are posted to the webhook you gave.
  • Stripe: if you pay for Pro, Stripe processes the payment and handles your card details. CodeSpend never sees card numbers.
  • Hosting: the website is served by Vercel, which keeps standard request logs.

Nothing is sold or shared for advertising.

Keeping and deleting data

  • Remove next to a connection deletes its stored key and all usage synced with it, immediately. Also revoke the key in the vendor's console: that is the only way to be sure it can't be used.
  • Delete branch data in the branch view deletes a project's branch reports.
  • To delete everything else (budgets, emails, webhooks), delete the data file on your own server. If someone else runs the server, write to . It is done within 30 days, and you get a confirmation.

Security

Data lives on the operator's server, in one file that only the server's user can read, with keys and webhooks encrypted inside it. Use read-only or reporting-only keys where the vendor offers them.

Changes

Changes to this policy are posted on this page with a new date. Material changes are announced to paying customers by email first.
